# kube-noob tools

Generated by scripts/build_skill.py from the bundled server code; run any of them with
`python3 -I scripts/kn.py TOOL '<json arguments>'`. Arguments marked * are required.

## api_history

API removal history and version map. Removed/deprecated Kubernetes APIs relevant to a target version, and the OpenShift->Kubernetes version map.

- `kind` (null/string)
- `platform` (string)
- `version` (null/string)

## audit_manifests

Audit manifests. Full deterministic audit: security, network exposure, storage access modes, reliability and red-team scenarios. Findings carry rule ids, line numbers, fixes, citations and matching RHACS policy names.

- `exceptions` (null/string): An exception list (YAML, apiVersion kube-noob.io/v1, kind ExceptionList): each entry names a rule, a scope, an owner, a reason and an expiry date. Active entries hide the findings they cover; expired and refused entries are reported and fail the gate.
- `manifests`* (string): One or more YAML documents (Kubernetes/OpenShift objects).
- `min_severity` (string): Hide findings below this severity.
- `platform` (string): Target platform.
- `stages` (array)
- `version` (null/string): Platform version, e.g. '4.22' (OCP) or '1.35'.

## build_diagnose

Diagnose a failed build log. Read a failed GitHub Actions, Jenkins, Tekton or OpenShift build log: the failing step (and why it is that step), the error line and its template, the cause class (dependency fetch, compile, test, image push, registry auth, quota, timeout, out of memory, permissions) with its evidence, reported issues, team memory and the fix for that CI system. Read-only.

- `log`* (string): A failed build or pipeline log: GitHub Actions, Jenkins, Tekton (tkn ... logs) or an OpenShift build (oc logs build/<name>). The end of the log matters most: when cutting, keep the end.
- `platform` (null/string)
- `version` (null/string): The cluster's OpenShift version, for reported issues that may apply.

## check_network_policy

Would this traffic be allowed?. Evaluate NetworkPolicies offline: can the source reach the destination on this port? Checks egress from the source and ingress to the destination, names the policy and rule that decide each, says why the other rules did not match, and proposes the smallest NetworkPolicy that would allow it.

- `default_namespace` (string): For objects without one.
- `destination`* (string): Where it goes: namespace/name of a workload (namespace/kind/name when names clash), namespace:key=value,... for a set of pod labels, or an IP address / CIDR outside the cluster.
- `manifests`* (string): The NetworkPolicies and the workloads they apply to (Deployments, Pods ...); add Namespace objects when policies select namespaces by label.
- `platform` (null/string)
- `port`* (integer/string): Destination port number (1-65535) or a named container port.
- `protocol` (string)
- `source`* (string): Where the connection starts: namespace/name of a workload (namespace/kind/name when names clash), namespace:key=value,... for a set of pod labels, or an IP address / CIDR outside the cluster.

## clarify_requirements

Clarify requirements. Check a (partial) generator blueprint and return blocking questions and stated assumptions.

- `blueprint`* (object): Partial blueprint; missing/invalid fields become questions.

## config_status

Show configuration. Effective configuration (webEnabled, cluster access, model), version and knowledge stats.

- no arguments

## diagnose

Diagnose symptoms offline. Match pasted events / describe output / logs / CLI errors or an Alertmanager webhook payload against troubleshooting playbooks, ranked by matching patterns and by the signals the text carries (alert names, reasons); returns the signals, ranked root causes, read-only checks with names filled in, fixes, reported issues for the version and policy denials.

- `limit` (integer)
- `platform` (null/string)
- `text`* (string): Events, `describe` output, logs, CLI errors, status JSON or an Alertmanager webhook payload (its alerts are read as text; an `openshift_version` or `version` label gives the version).
- `version` (null/string): The cluster's OpenShift version (4.20 or 4.20.8): leaves out reported issues already fixed there.

## explain_denial

Why was this denied?. Explain an admission denial policy by policy: Kyverno, OPA Gatekeeper, ValidatingAdmissionPolicy, Pod Security Admission, OpenShift SCC, RHACS, ResourceQuota, LimitRange or RBAC. Returns the policy and rule, the failing field, read-only commands with names filled in, the fix (with a patch for Pod Security and RBAC) and the audit rules that catch it before deploy.

- `platform` (null/string)
- `text`* (string): The denial as printed: `kubectl apply` or `oc apply` output, a FailedCreate event or a Warning.

## explain_rule

Explain an audit rule. Rationale, remediation, citations for a rule id.

- `rule_id`* (string): e.g. KN-S001

## extract_signals

Extract signals. Read the canonical names in an error: Alertmanager alert names (webhook payload or text), event and ClusterOperator condition reasons, container reasons, admission rules, components and normalised error templates, plus the alerts its words imply. Returns each signal with where it was found, the catalogue entry (components, playbooks, upstream source) and the playbooks it points at. Read-only and offline.

- `text`* (string): An Alertmanager payload, events, a ClusterOperator, pod status, logs or an error in words.

## fix_manifests

Apply safe mechanical fixes. Migrates removed APIs, fixes wrong API groups, hardens securityContext, adds Route TLS, unblocks PDBs, reorders EgressFirewall rules, swaps RWO-only classes for RWX claims. Returns the diff log and manual follow-ups. Does not touch any cluster.

- `harden` (boolean): Apply securityContext hardening (restricted profile).
- `manifests`* (string): One or more YAML documents (Kubernetes/OpenShift objects).
- `platform` (string): Target platform.
- `version` (null/string): Platform version, e.g. '4.22' (OCP) or '1.35'.

## generate_helm_chart

Generate a Helm chart. Same as generate_manifests but packaged as a Helm chart (Chart.yaml v2, values.yaml, values.schema.json, templates). Returns file contents.

- `blueprint`* (any)

## generate_manifests

Generate production manifests. Deterministic, audited manifests for kubernetes / openshift / rosa-classic / rosa-hcp from a blueprint (name, namespace, image, replicas, port, probes, storage, exposure, egress).

- `blueprint`* (any)

## get_knowledge

Read a knowledge chunk or document. Fetch the full text of a chunk id (kn:<doc>#<n>) or every chunk of a document id.

- `id`* (string): Chunk id 'kn:<doc>#<n>' or a document id.

## grade_answer

Grade a model answer (enforcer + credit system). Deterministic reward for a completion against a benchmark task: task correctness (audit engine or QA rules), source-attribution credit for valid [kn:...] citations, format, penalties.

- `completion`* (string)
- `task` (null/object): Inline task. Its mustMention / mustNotMention / matches entries are matched as literal text, not regular expressions (only built-in benchmark tasks use regular expressions).
- `task_id` (null/string): Benchmark task id; or pass `task` inline.

## incident

One incident in full. An incident with its evidence (redacted), diagnosis, policy denials, reported issues, rollout change, every occurrence, the fixes a person confirmed, and confirmed fixes for the same problem elsewhere.

- `id`* (string): Incident id, e.g. inc-3fa94c0e12.

## incident_confirm

Remember the fix for an incident. AFTER the user confirms it worked: store the cause and fix on the incident (and as a learning note), so the next occurrence comes with it. Summaries only; never leaves the machine.

- `cause`* (string): The confirmed root cause, in words.
- `confirmed_by_user`* (boolean): True only after the user explicitly confirmed this cause and fix worked.
- `fix`* (string): What fixed it, in words (no manifests).
- `id`* (string): Incident id, e.g. inc-3fa94c0e12.

## incidents

Incidents the watch has seen. Open (or resolved) incidents from the local incident ledger: workload, signal, how often it came back, the diagnosis and what changed before it started. Read this first when asked what is wrong.

- `limit` (integer)
- `namespace` (null/string)
- `status` (string): Which incidents to list.

## insight

What is this, and what does it say?. Start here for anything the user pastes. Names what the input is (events, pod status, logs, an Alertmanager payload, a policy denial, a ticket, manifests, a Helm template, a build log, a Containerfile, an SBOM or scanner report, a packet trace, must-gather paths, a question; several at once) and runs every analyser that applies: diagnosis with reported issues and team memory, the denial explainer, the audit, the documentation. Returns every finding with its source, read-only next steps and what was not analysed and why. Read-only, local.

- `platform` (null/string)
- `text`* (string): Anything pasted: events, describe output, logs, an Alertmanager payload, a policy denial, a ticket, manifests or a Helm template, a build log, a Containerfile, an SBOM or scanner report, or a question.
- `version` (null/string)

## known_issues

Is this a reported issue?. Match an error or symptom against the issues listed in the OpenShift release notes (known issues and issues fixed in each update) and, when this install keeps a local copy of Red Hat's public Jira, against those tickets too. Returns the issue id and link, what became of it (fixed and in which version, still open, closed as not a bug, won't fix or a duplicate), the workaround and Red Hat's remarks from the comments; with `version`, only issues that can affect that version.

- `limit` (integer)
- `platform` (null/string)
- `text`* (string): An error message, events, logs or a symptom in words.
- `version` (null/string): The cluster's OpenShift version (4.20 or 4.20.8): keeps only issues that can affect it.

## learning_note_add

Remember a confirmed fix. Save a short symptom -> cause -> fix note to the local learning file AFTER the user confirms it worked. Summaries only: credentials, manifests and raw logs are rejected. Never leaves the machine.

- `cause`* (string): The confirmed root cause.
- `confirmed_by_user`* (boolean): True only after the user explicitly confirmed this cause and fix worked.
- `fix`* (string): What fixed it, in words (no manifests).
- `platform` (null/string)
- `symptom`* (string): What was observed, in one or two sentences.

## learning_profile_set

Remember the user's environment. Save platform, versions and team conventions the user stated, so later answers fit their setup.

- `conventions` (array/null): Team conventions, e.g. 'namespaces are <team>-<env>'.
- `platform` (null/string)
- `versions` (object): Keys kubernetes|openshift|helm|rhacs|rosa, values like '4.22'.

## learning_summary

Show what kube-noob has learned locally. The user's environment profile (platform, versions, conventions), confirmed troubleshooting notes (cite as [kn:local-N#0]) and the most frequent playbooks/rules. Read this before tailoring advice.

- no arguments

## list_rules

List audit rules. All rule ids with stage, category and default severity.

- no arguments

## policy_generate

Turn audit rules into admission policies. Generate ValidatingAdmissionPolicy (with binding) and/or Kyverno ValidatingPolicy YAML from kube-noob's audit rules, in audit (warn and record) or enforce mode, for a platform. One policy per rule decidable from one object; each names its rule, fix and source. Rules that need other objects or that the API server already enforces are listed with the reason. Nothing is applied.

- `engines` (array): vap: ValidatingAdmissionPolicy + binding (built into Kubernetes 1.30+); kyverno: Kyverno ValidatingPolicy (policies.kyverno.io/v1, Kyverno 1.18+).
- `exceptions` (null/string): An exception list (YAML, kube-noob.io/v1 ExceptionList): active entries become exemptions in their rule's policy (with the ReplicaSets and pods their workloads make); expired or refused ones are listed.
- `exclude_namespaces` (array): Namespaces the policies skip, besides kube-system, kube-public and kube-node-lease.
- `mode` (string): audit warns and records; enforce refuses
- `platform` (string)
- `rules` (array): Rule ids such as KN-S001 (default: every rule).
- `version` (null/string): OpenShift (4.20) or Kubernetes (1.33)

## posture_report

Latest drift and policy report. The newest daily report in this install's data folder: objects added, removed and changed since the previous snapshot (with the fields that changed), findings new and fixed, and open findings by namespace, owner and rule. Local data only.

- no arguments

## posture_scan

Attack paths in manifests. Rank the paths from an exposure (Route, Ingress, LoadBalancer or NodePort Service) to what a compromised pod could do: node access (privileged, hostPath, host namespaces) or Kubernetes API rights through its ServiceAccount token (read Secrets, exec, create workloads, escalate). Score = exposure x blast radius; every step names the field that proves it, with a fix. Secret objects are dropped unread.

- `manifests`* (string): Routes, Ingresses, Services, workloads, ServiceAccounts and RBAC objects (YAML). Secret objects are dropped unread.
- `top` (integer): How many ranked paths to return.

## red_team

Red-team manifests. Hostile-auditor scenarios: node crash, zone outage, RWX split-brain, exposure, privilege escalation, upgrade blocking, secret leaks, resource starvation, supply chain.

- `manifests`* (string): One or more YAML documents (Kubernetes/OpenShift objects).
- `platform` (string): Target platform.
- `version` (null/string): Platform version, e.g. '4.22' (OCP) or '1.35'.

## rhacs_compare

Compare RHACS policies with kube-noob's rules. Map every policy in an RHACS (StackRox) export to kube-noob rules by name and criteria: overlap (same setting, with severity and scope differences), related (the same risk seen through image, runtime or API-event data), gap (a deploy-time setting kube-noob has no rule for), outside (image contents, runtime behaviour, API events, label conventions) or unexplained (criteria kube-noob does not know). Lists disagreements and the rules no policy covers. Local only.

- `outcomes` (array): Only return policies with these outcomes (default: all).
- `policies`* (string): An RHACS policy export as JSON: {"policies": [...]} from the RHACS portal (Export policy to JSON) or POST /v1/policies/export, a list of policies, or one policy.

## run_protocol

Run the 7-step engineering protocol. Clarify -> Validate -> Research -> Audit -> Calibrate -> Generate -> Red Team for a request with existing manifests or a generator blueprint. Returns the Audit & Validation Brief, the production manifest, and Red Team findings with safeguards. Use this first for any design/review request.

- `apply_fixes` (boolean)
- `blueprint` (null/object): Generator blueprint (see generate_manifests).
- `manifests` (null/string): Existing manifests to review.
- `platform` (null/string)
- `request`* (string): What the user wants, in their words.
- `version` (null/string)

## search_knowledge

Search local knowledge. BM25 search over the built-in curated knowledge and the ingested corpus (Kubernetes/OpenShift/ROSA/Helm/StackRox docs, Terraform modules, public RHACS Jira insights). Results include chunk ids to cite as [kn:...] plus source URL and license.

- `limit` (integer)
- `query`* (string)
- `source` (null/string): Source id prefix filter, e.g. 'builtin:', 'jira:ROX', 'k8s-docs'.

## threat_model

STRIDE threat model of an application. From manifests: entry points, trust boundaries, data stores and identities, and per element the STRIDE threats with status (open, mitigated, not assessed), the evidence, the kube-noob rules, generated admission policies and RHACS policies that mitigate each, and MITRE ATT&CK for Containers technique ids. Deterministic; Secrets are dropped unread.

- `manifests`* (string): The application's YAML.
- `platform` (null/string)
- `reports` (array): Optional scanner reports of its images, to assess public-facing exploits (threat TM-E01).
- `version` (null/string)

## ticket

Look up a Red Hat Jira ticket. One ticket from this install's local copy of Red Hat's public Jira (OCPBUGS, ROX, HOSTEDCP...): its status, what became of it, fix versions and whether `version` already has the fix, the workaround and remarks from the comments, and linked tickets. Local data only; nothing is fetched.

- `key`* (string): A Red Hat Jira key, e.g. OCPBUGS-12345 or ROX-30000.
- `version` (null/string): The cluster's OpenShift version: says whether the fix is already in it.

## ticket_changes

What changed in Red Hat Jira. Reconcile the local copy of Red Hat's public Jira: tickets fixed (with fix versions), closed as not a bug, won't fix or duplicate, reopened, given a fix version or opened since a date, with links, and the open tickets per project and verdict. Read-only and local; each sync records the changes.

- `kinds` (array)
- `limit` (integer)
- `project` (null/string)
- `since` (string): How far back: 2d, 36h, 90m or a date such as 2026-10-25.

## upgrade_risks

Known risks for an OpenShift update. Before updating OpenShift from one x.y.z version to another: the risks Red Hat declares for that update in the public update graph (conditional updates, as an OpenShift Update Service serves them), from a bundled snapshot, offline. Each risk has its name, message, link, the version that fixes it and a verdict: applies (declared for every cluster), check (one fact decides it, with the read-only command or must-gather file that shows it) or cannot evaluate offline (its PromQL, as written). Whether the update is in your channel is not checked.

- `arch` (null/string): The release architecture (multi for a multi-architecture payload). Without it, every architecture is checked and a risk declared for some of them only says which.
- `current`* (string): The OpenShift version the cluster runs, x.y.z, e.g. 4.20.3.
- `target`* (string): The version to update to, x.y.z, e.g. 4.21.4.

## validate_manifests

Validate manifests. Strict schema validation (Kubernetes 1.35 + OpenShift/OVN-K/StackRox/Gateway API CRDs), apiVersion vs kind, OpenShift-only APIs on vanilla Kubernetes, removed/deprecated APIs, selector wiring.

- `manifests`* (string): One or more YAML documents (Kubernetes/OpenShift objects).
- `platform` (string): Target platform.
- `version` (null/string): Platform version, e.g. '4.22' (OCP) or '1.35'.

## vuln_report

Assess scanner output: VEX, exploitation, reachability. Read Trivy or Grype JSON, CycloneDX or SPDX SBOMs, or an RHACS image scan into one finding per package, version and CVE (with the fix version); apply Red Hat VEX (a not-affected or already-fixed finding drops out, citing the statement); mark CISA KEV entries; and, with the manifests, rank by exposure, privileges and RBAC reach with each finding's attack path. SBOM packages are matched against Red Hat VEX. Local only.

- `image` (null/string): Treat every report as this image (registry/repo:tag or @sha256:...).
- `kev` (null/string): Optional: the CISA KEV catalog JSON (known_exploited_vulnerabilities.json, CC0).
- `manifests` (null/string): Optional: the YAML that runs the images; findings are then ranked by exposure and privileges and shown with their attack path.
- `products` (array): Red Hat product CPE prefixes the images belong to (default: from the RHEL release in the report, e.g. cpe:/o:redhat:enterprise_linux:9).
- `reports`* (array): Scanner output as JSON text: Trivy (trivy image -f json [--list-all-pkgs]), Grype (grype -o json), a CycloneDX or SPDX 2 JSON SBOM, or an RHACS image (GET /v1/images/{id}). Reports of the same image are assessed together.
- `top` (integer): How many ranked findings to return.
- `trust_report_vex` (boolean): Honour a CycloneDX report's own analysis (not_affected, resolved, false_positive). Off by default: the findings it marks are kept, with a note.
- `vex` (array): Optional Red Hat CSAF VEX documents (JSON) to apply on top of the local redhat-vex corpus.
